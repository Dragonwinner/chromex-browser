## 🛠️ Prerequisites

Before you start, make sure you have the following installed:

- **[Node.js](https://nodejs.org/)** (v18 or higher recommended)
- **[npm](https://www.npmjs.com/)** (comes with Node.js)
- **[Visual Studio Code](https://code.visualstudio.com/)** or **[Cursor](https://www.cursor.com/)**
- **[Google Chrome](https://www.google.com/chrome/)**, **Microsoft Edge**, or **Brave Browser** installed on your machine.

## 💻 Local Development Setup

### 1. Fork & Clone
Fork the repository on GitHub, then clone your fork:

```bash
git clone https://github.com/YOUR-USERNAME/chromex-browser.git
cd chromex-browser
```

### 2. Install Dependencies
```bash
npm install
```

### 3. Build the Extension
```bash
npm run build
```

*(Or run `npm run watch` to automatically rebuild when you make changes).*

### 4. Run & Debug in VS Code
1. Open the project folder in VS Code (`code .`).
2. Press **`F5`** (or go to **Run and Debug** → select **"Run ChromeX Browser Extension"**).
3. A new **Extension Development Host** window will open.
4. In that window, press `Ctrl + Shift + P` → run **`Open Full Browser`** to test your changes live!

## 🏗️ Project Architecture

```
chromex-browser/
├── extension.js           # Main Extension process (Puppeteer controller, CDP sessions, input dispatch)
├── dist/
│   └── extension.js       # Bundled output generated by esbuild (runtime entry point)
├── media/
│   ├── browser.js         # Webview Client script (Canvas rendering, event capture, UI handlers)
│   ├── browser.css        # Webview styling, toolbar, bookmarks bar, dark/light theme
│   ├── icon.png           # Extension logo (128x128)
│   └── *.png              # Feature preview screenshots
├── package.json           # Extension manifest, commands, settings, and npm scripts
├── .vscode/
│   ├── launch.json        # F5 debug launcher configuration
│   └── tasks.json         # Pre-launch build task
├── README.md              # User documentation and marketplace showcase
└── CONTRIBUTING.md        # Contribution guidelines (this file)
```

### How It Works:
1. **Host Side (`extension.js`)**:
   - Launches a local Chromium browser offscreen using `puppeteer-core`.
   - Attaches a Chrome DevTools Protocol (CDP) session.
   - Pushes video frames via `Page.startScreencast`.
   - Auto-detects Widevine CDM modules for DRM video playback.
   - Dispatches mouse and keyboard events to Chrome via `Input.dispatchMouseEvent` and `Input.dispatchKeyEvent`.
2. **Client Side (`media/browser.js` & `browser.css`)**:
   - Runs inside the VS Code Webview panel.
   - Renders incoming JPEG frames to an HTML5 `<canvas>` using `requestAnimationFrame`.
   - Captures mouse clicks, wheel scrolls, drag-and-drop, and keystrokes, forwarding them to the extension host.

## 🔄 Development Workflow

### Modifying Backend Logic (`extension.js`):
- Run `npm run watch` in a terminal.
- In the Extension Development Host window, press `Ctrl + R` (or `Ctrl + Shift + P` → **`Developer: Reload Window`**) to reload the extension.

### Modifying Frontend / UI (`media/browser.js` or `media/browser.css`):
- Webview assets are served directly from `media/`.
- Simply close and reopen the browser tab in your Extension Development Host to see styling and client script changes instantly.

## 🧪 Debugging Tips

### 1. Debugging Extension Host Backend:
- Set breakpoints directly in `extension.js` inside VS Code before pressing `F5`.
- View console output in the **Debug Console** tab (`Ctrl + Shift + Y`).

### 2. Debugging Webview Frontend (Canvas & UI):
- In the Extension Development Host window, press `Ctrl + Shift + P` → run **`Developer: Toggle Developer Tools`**.
- Switch to the **Console** tab to view `browser.js` logs or inspect DOM elements in the **Elements** tab.

### 3. Packaging a `.vsix` Locally:
To test packaging without publishing:
```bash
npm run package
```
This generates `chromex-browser-1.0.2.vsix` in your root directory.

## 🚀 Submitting a Pull Request

1. **Create a Feature Branch**:
   ```bash
   git checkout -b feature/my-cool-feature
   ```
2. **Make your changes** and test thoroughly.
3. **Commit your changes**:
   ```bash
   git add .
   git commit -m "feat: add support for custom bookmark shortcuts"
   ```
   *(We follow [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `docs:`, `perf:`, `refactor:`).*
4. **Push to your Fork**:
   ```bash
   git push origin feature/my-cool-feature
   ```
5. **Open a Pull Request**:
   - Go to your fork on GitHub and click **Compare & pull request**.
   - Describe what changed and why.
   - Attach screenshots or recordings if you made UI changes!
